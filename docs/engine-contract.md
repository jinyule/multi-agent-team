# Codex 与 Claude Code：首轮接入契约

状态：用户已确定首轮同时接入两者；本文为 M2 设计，适配器尚未实现，尚未验证真实账户调用。

## 进程边界

| 引擎 | 接入建议 | 生命周期 |
| --- | --- | --- |
| Codex | 独立 app-server，结构化双向协议 | 由 teamd 启动并监管，退出窗口不影响它 |
| Claude Code | 官方 Agent SDK 的流式输入，独立 Node 适配进程 | 由 teamd 管理；正式分发提供配套 Node 运行时 |

不能接管用户正在使用的交互会话或共享 app-server 的其他任务。平台运行记录引用自己创建或明确绑定的引擎会话；成员身份与引擎会话分开。使用具体配置/凭据的方式在接入阶段验证，不复制账户秘密到数据库、命令文本或日志。

## 平台内部命令

每条命令包含 `protocol_version`、`request_id`、`run_id` 和 `generation`。只有引擎适配进程能够上报自身运行结果；模型文本不是控制指令。

| 命令 | 主要输入 | 必须区分的结果 |
| --- | --- | --- |
| `capabilities` | 引擎版本与配置引用 | 支持、部分支持、不可用及具体原因 |
| `open_session` | 成员、工作区、执行政策、可选恢复会话 | 新建、恢复成功、恢复不支持、历史不兼容 |
| `submit` | 目标/任务版本、输入、上下文引用 | 已接受及关联请求；最终完成通过事件返回 |
| `respond_approval` | 当前请求 ID、规范化操作摘要、一次性决定 | 允许、拒绝、已失效、请求不匹配 |
| `interrupt` | 活动执行关联、预期代次 | 已请求中断、已停止、无法保证停止 |
| `close_session` | 是否仍有活动/排队输入 | 关闭完成或需先收拢运行，不暗中丢弃排队任务 |
| `usage` | 运行/会话标识 | 实测、估算、不可获取；当前或最终计量 |

标准化事件包含运行标识、来源、序号/游标、时间和原始记录引用，类型至少区分：会话就绪、消息、工具请求/结果、审批等待、用量、活动完成、失败、已中断、进程结束。完成一次模型活动不直接等于项目任务通过验收。

不要求暴露模型隐藏思维。保留可展示的说明、实际动作、输出、决策依据和验证证据即可。

## 审批、中断与恢复

- Codex 使用 app-server 的请求关联与审批响应；具体字段从实际安装版本的协议生成或核对，不凭记忆硬编码未知枚举。
- Claude SDK 使用权限回调处理未被更早规则决定的操作；已有 hook、deny、allow 和 permission mode 的影响必须进入能力测试。不能宣称所有调用都一定经过一个回调。
- 平台预授权只适用于可核验的具体操作与工作区，不自动开启全局绕过审批。授权失效、进程断开或未知请求默认不放行。
- 中断先保存请求，再等待引擎确认和进程/工具收拢；超时进入待核对状态。不能只给进程发送信号就立刻释放工作区给下一个写者。
- 会话恢复保存的是引擎支持的历史/检查点；文件、进程及远端状态另外核对。丢失响应后不盲目重发会产生副作用的请求。

## 两个引擎都必须通过的接入验收

1. 在独立测试目录建立会话，读取或修改范围符合预设政策，保存真实结构化结果。
2. 正常完成、模型错误、限流、进程退出和客户端断开能够分别表达。
3. 工具拒绝时无对应写入；允许时操作与被批准的规范化参数一致；过期或错配审批无效。
4. 中断后核对活动和后续排队输入；重启恢复时不重复已经完成的动作。
5. 引擎执行环境无法调用平台控制 socket 或篡改平台数据/证据；同时能使用所需模型认证。
6. 记录用量能力及停止后的在途费用局限。无可用计量时明确采用已约定的替代预算规则。
7. 首先用可控 provider/测试端验证协议与失败路径，再用有界真实账户调用验证兼容性；模型版本与额度不在未确认时擅自作长期配置。

通过上述契约不等于已经具备 TDD、独立检视或质量门禁；这些仍由平台调度与质量模块负责。
